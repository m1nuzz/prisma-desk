# Внешние плееры и PotPlayer в Prisma Desk

## Что добавлено

Windows-версия Prisma Desk теперь умеет выбирать внешний проигрыватель из отдельного меню. Поддерживаются сохранённый VLC-путь, **PotPlayer x64**, ручной выбор `PotPlayerMini64.exe`/`PotPlayerMini.exe` и режим «Другой плеер». Для режима «Другой плеер» остаётся только запуск; чтение таймкода доступно только для нативно поддержанного PotPlayer.

Для PotPlayer путь по умолчанию проверяется в том числе по адресу:

```text
C:\Program Files\PotPlayer\PotPlayerMini64.exe
```

Также проверяются `Program Files (x86)`, исторический каталог `DAUM\PotPlayer` и Windows App Paths/установочные записи, если они доступны.

## Как выбрать PotPlayer

В настройках Prisma откройте раздел приложения и выберите **«Внешний проигрыватель»**. Затем выберите **«PotPlayer x64»**, если автоопределение нашло установленный файл, или **«Выбрать PotPlayer вручную»**, если приложение находится в другом каталоге. После выбора Prisma Desk сохраняет путь и тип плеера в настройках Prisma; редактировать `PotPlayerMini64.ini` не требуется.

При запуске Prisma Desk передаёт URL и сохранённую позицию параметром `/seek=<секунды>`. Если ранее сохранённой позиции нет, видео начинается с начала. Запуск выполняется с `/new`, чтобы сессия Prisma Desk не подключилась к случайно открытой очереди другого PotPlayer.

## Как работает синхронизация

Во время воспроизведения Prisma Desk каждые две секунды запрашивает у окна PotPlayer текущий таймкод и длительность через Win32 `WM_USER` messages. Запрос выполняется с ограничением времени, поэтому зависший или закрытый PotPlayer не должен блокировать интерфейс. После запуска предусмотрено 30 секунд grace period: если окно ещё не появилось или URL ещё загружается, polling повторяется, а сессия не закрывается преждевременно. Время хранится в секундах, а запись выполняется примерно раз в десять секунд либо при заметном изменении позиции; при закрытии выполняется финальная запись.

Прогресс привязывается к идентификатору фильма/эпизода из данных Prisma и дополнительно к режиму запуска. Это важно для сериалов: позиция одного эпизода не должна попасть в другой. Когда Prisma предоставляет публичный `Prisma.Timeline`, Prisma Desk вычисляет совместимый hash и вызывает тот же `Prisma.Timeline.update({ hash, percent, time, duration })`, который использует встроенный проигрыватель. Благодаря этому карточки, история и синхронизация аккаунта видят прогресс внешнего PotPlayer тем же способом, что и VLC. Хранилище `prisma_desktop_external_progress_v1` используется как локальный fallback и дублируется в Tauri `store.json`, поэтому внешняя сессия не зависит от памяти PotPlayer.

Контент считается просмотренным, когда известная длительность достигнута не менее чем на 92% либо осталось не более десяти секунд. После этого для следующего запуска позиция сбрасывается в начало. Если длительность неизвестна, позиция сохраняется, но автоматический статус «просмотрено» не выставляется.

## Диагностика

Если PotPlayer запускается, но прогресс не обновляется, проверьте следующие условия:

1. Prisma Desk и PotPlayer должны быть запущены с одинаковым уровнем прав Windows. Если один процесс запущен «от имени администратора», а другой нет, Windows может ограничить межпроцессные сообщения.
2. В настройках должен быть выбран именно PotPlayer, а путь должен заканчиваться на `PotPlayerMini64.exe` или `PotPlayerMini.exe`. Режим «Другой плеер» не обещает синхронизацию.
3. Для сетевого URL нужно сохранять исходную ссылку без ручного удаления query-параметров: она используется как часть запуска, а стабильный Prisma ID — как ключ прогресса.
4. После изменения пути перезапустите текущий запуск видео, чтобы новая сессия получила новый PID и окно PotPlayer.

На Unix-платформах PotPlayer-команды и Win32 observer не активируются; существующие протоколы внешних плееров продолжают работать как раньше.

## Технический контракт

| PotPlayer message | Назначение | Единицы |
|---|---|---|
| `WM_USER + wParam 0x5002` | Полная длительность | миллисекунды |
| `WM_USER + wParam 0x5004` | Текущая позиция | миллисекунды |
| `WM_USER + wParam 0x5005`, `lParam=milliseconds` | Установить позицию | миллисекунды |
| `WM_USER + wParam 0x5006` | Состояние: `-1` stopped, `1` paused, `2` running | enum |
| `/seek=<time>` | Начальная позиция | секунды или `hh:mm:ss.ms` |

Эти сообщения основаны на практических community-реализациях PotPlayer automation, а не на гарантированном публичном SDK. Поэтому значения изолированы в `src-tauri/shared/services/player.rs`, результат проверяется на диапазон и тайм-аут, а отсутствие ответа никогда не перезаписывает сохранённую позицию нулём. Если текущая версия Prisma не экспортирует `Prisma.Timeline`, продолжение всё равно работает через локальный fallback; после обновления Prisma совместимый Timeline подключается автоматически.

## Файлы реализации

`src-tauri/shared/services/player.rs` содержит Windows-specific обнаружение, запуск и IPC. `src-tauri/core/lib.rs` регистрирует Tauri-команды `player_detect`, `player_choose_path`, `player_validate`, `player_start`, `player_read_state` и `player_seek`. `src-tauri/module/bridge.js` предоставляет эти команды через `window.desktopAPI.player`. `src-tauri/module/client-inject.js` добавляет меню выбора, перехватывает `Prisma.Player.play`/`iptv`, управляет session polling/progress persistence и публикует диагностический snapshot.

## Строгая проверка таймкода на Windows 11

Для проверки самого PotPlayer, независимо от Prisma, запустите PowerShell с тем же уровнем прав, что и Prisma Desk:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\potplayer-ipc-diagnostic.ps1 `
  -PotPlayerPath 'C:\Program Files\PotPlayer\PotPlayerMini64.exe' `
  -Url 'https://<стабильный-тестовый-url>' `
  -OutFile "$env:USERPROFILE\Desktop\potplayer-ipc-result.json"
```

PASS разрешён только если скрипт нашёл видимое окно класса `PotPlayer`/`PotPlayer64`, получил положительную длительность и статус `2`, увидел не менее пяти изменяющихся позиций и прошёл `0x5005 → 0x5004` seek round trip с ошибкой не более 1,5 секунды. Если PID запускающего процесса отличается от PID окна, скрипт явно укажет `fallbackUsed=True`; это допустимая и важная диагностическая ситуация.

После PASS откройте фильм через Prisma Desk, подождите не менее 20 секунд и проверьте в DevTools WebView или в консоли Prisma:

```js
window.__desktop_external_progress_diagnostics
```

Для подтверждения Prisma-интеграции нужны `successfulReads >= 5`, изменяющийся `lastState.positionSec`, `timelineUpdates >= 1`, заполненные `lastState.window` и `lastTimelineUpdate`, а при повторном запуске — `lastResumePositionSec` около ранее сохранённого времени. Без этого нельзя считать проблему решённой только по факту открытия PotPlayer.
